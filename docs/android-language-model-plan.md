# Android 构建模型提供者实施计划

日期：2026-10-27。用户批准先落档、再实施、分步提交。
宿主计划：[插件构建模型协作](../../asterlyn/docs/engineering/2026-10-27-plugin-build-model-cooperation-plan.md)，ADR-0035；宿主文档提交 `6b7df57`。

## 责任

本插件拥有 Gradle/AGP 版本适配、构建根与模块、真实变体/source sets/编译依赖、Android boot classpath、已有生成源码及模型 schema/缓存失效规则。模型提取器作为本插件的完整性覆盖附属资源，经宿主通用进程能力执行；隔离 JS 不获得文件/进程 API，不在 30 秒回调锁里跑 JVM。

宿主掌握通用包准入、工具身份、执行授权、工作/取消/回收、受控制品缓存和引用；LSP 插件负责消费和后端适配。仅启用本插件或使用 Tasks/Run 不默认运行完整语义导入；首次语言消费者需要时才提取并合并相同请求。

## 强依赖产品规则

LSP 插件整体启用时，本插件必须保持启用，不能关闭/卸载或切到破坏依赖约束的版本。用户先关闭 LSP 后解除其依赖锁；本插件不会随 LSP 自动关闭。此规则与是否为 Android 项目、LSP 是否运行或崩溃无关；启用不等于执行授权。

关系在 LSP 静态 manifest 声明，宿主原生统一维护；本插件不维护依赖者计数或判断其他插件的私有状态。多个消费者存在时须全部解除后才可关闭。缺失/不兼容依赖拒绝启用消费者，不隐式下载。

## 分步实施

1. C1：配合宿主 SDK 和 LSP 包声明，验证强依赖门禁、UI 原因、旧包兼容；本插件现有 Tasks/Run/Devices 保持回归。
2. C2：使用宿主版本化模型提供能力，控制消息只传状态、generation 和制品引用；生命周期和访问范围由宿主校验。
3. C3：附属提取器先验证 boostCleaner 一个模块/变体的真实 AGP 模型，再扩展依赖模块、SDK/AAR/source attachment 和 worktree；日志区分连接、配置、模型、解析、写出阶段。
4. C4：LSP 消费相同模型并证明真实定义/引用/hover/completion、dirty buffers 和诊断版本。任务名推导不是模型权威；应用选择由模型解析到各依赖模块的实际变体。

模型和任务目录有独立缓存 schema，复用构建输入监测和选择意图。默认不构建 APK、不运行生成/处理器任务；离线也不被描述成隔离环境。无全局停止 Gradle daemon；只取消所属工作。不同工作区/输入指纹/选择/工具身份模型不混用，陈旧结果不可覆盖新模型。

每步记录功能、负向测试、耗时、内存范围、包影响和已知限制。未获得模型与后端语义成功证据，不声称 Android LSP 可用。SDK 精确 vendor 并标明开发制品；不发布远端。
