# 语言模型失败诊断补强

日期：2026-10-30；基线 0.6.2。配合宿主语言服务生命周期计划，先落档再修改。

- 保持 Gradle/AGP 模型提取在本插件，宿主不执行 Android 特定推断。
- 当前原生日志显示模型进程约 5–6 秒后失败，但 worker 仅报告 error 且 causeClass 为空。
  首先补充安全分类（配置/依赖/TLS/工具/取消/超时/模型校验）和有限异常类型链，保留阶段与耗时。
- 原始 stderr、凭证、项目属性值和用户源文不回传给 UI/日志。详细元数据仅在宿主显式调试期开启；
  正常失败仍有精简原因。保持输出/时限/进程树取消和模型完整性边界。
- 用受控失败夹具验证分类和脱敏，再对 FilesRecovery 实测。基于证据修正根因，不能通过关闭 TLS、
  修改凭证或虚构缺失依赖的 classpath 使模型“成功”。
- 如修改包，升级本地版本，执行类型检查、现有模型/协议测试、完整包检查和原生模型验收；记录
  性能、资源及未解决的项目条件。按阶段本地提交，不推送/发布。

## 2026-10-30 实施记录

- 0.6.3 修正不存在的环境凭证被补成空 `-P` 参数的错误，保留项目真实配置；未修改业务项目、凭证、TLS 或仓库设置。
- 无任务列表/运行配置时，由 AGP 的真实模型选择应用模块（优先 `:app`）、debug 构建类型及稳定排序的实际变体；显式选择不存在时拒绝导入，不静默切换。
- 模型程序输出有限错误类别；调试时增加有界异常类型链、脚本 basename/行号。按行重组 JVM 分片输出，不输出原始异常消息、凭证、源码或完整路径。
- 属性覆盖顺序参考 [Gradle 项目属性文档](https://docs.gradle.org/current/userguide/build_environment.html#sec:project_properties)。本次根因由代码路径和真实模型探针共同确认。
- `npm run verify`：74 项通过。FilesRecovery 自动选择实际变体导入 6 个模块约 14.9 秒；boostCleaner 显式 cleanx100Debug 导入 25 个模块约 14.7 秒。失效旧变体被明确拒绝。
- 宿主联调和最终安装证据在宿主生命周期计划中维护。
